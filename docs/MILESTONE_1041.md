# Milestone10.4.1 — local regression fixes and conversational interpretation

Baseline: source4e5ae51 remains deployed at https://holobuild.vercel.app. These changes are local and require explicit owner approval before push/deployment. Prior public10.4 validation receipts are preserved separately. No Milestone11.

## Confirmed causes and targeted corrections

Structure Examples wrote generationStore.prompt, but the new assistant composer displayed a separate React draft. The example therefore changed hidden state instead of the visible input. StructureGenerator now receives an example callback from VoiceCommands. That callback fills the active composer, returns to Request view and focuses the input. It does not submit or spend a Gemini request. The established example list remains available under AI Help, with native buttons for mouse, keyboard and touch.

The assistant's phrase classifier was the only route for some unmatched requests. Flexible requests could fall into a generic deterministic error without reaching a provider. Supported deterministic commands and tested primitives remain fast paths; unmatched construction/conversation requests now reach a strict assistant interpretation endpoint. The model interprets language into a bounded create/compose/edit/clarify/explain/finish proposal. It does not execute code or mutate the scene. This is not another list of example-phrase aliases.

A new flexible request also needed to clear an older unconfirmed edit. Otherwise GenerationPreview could prioritize the old edit while the assistant described a new design. Superseded previews now clear before interpretation, preserving the confirmed scene. Request cancellation aborts interpretation and ignores late output; network, streamed errors, malformed output and deadlines settle into actionable assistant replies. There is no evidence establishing the friend's original historical device-specific cause, and no physical microphone acceptance is claimed.

## Interpretation architecture and boundaries

POST /api/planner/assistant uses the existing Gemini/native or compatible/Ollama provider adapter, streaming parser, allowlisted model, time budget, origin checks, structured safe references, Upstash admission and terminal lease release. One model interpretation consumes one normal admitted attempt, including a model clarification. There is no hidden second coordinate-generation call and no automatic retry loop. Limits remain5 requests/IP/minute,100 admitted attempts/UTC day and2 concurrent hosted generations. No paid service or configuration upgrade.

Create proposals contain a strict supported design specification. Custom compositions beyond the named templates can instead use the existing strict ConstructionPlan schema in a compose proposal, preserving the prior ability to generate supported primitive assemblies. Both paths use the same geometry/placement validators and one normal model admission. The existing bounded10000-token plan allowance is retained for compositions; no public request/quota limit changed. The application computes actual geometry using the existing tested construction primitives, then applies schema, geometry, explicit-attribute and placement validation. The source label says Gemini/LLM interpreted design with validated primitives; it never pretends these are model-invented coordinates or an unrelated Offline fallback. Existing explicit Offline templates and the direct LLM coordinate-plan path remain available. Seven supported structure templates are house, room, tower, office, warehouse, shed and bridge. Flexible synonyms can map to a supported design with an explanation or a focused clarification.

Edit proposals use the existing validated StructureOperation or a restricted selected-component color/material/transform. Part versus Structure selection, exact target UUID, requested role/floor, unchanged scene/selection and existing placement rules are checked before preparing a preview. All changes require confirmation and enter the existing command manager as one atomic history entry. Other objects and structures are not mutated. A model cannot redirect an all-parts request into a single component, or omit explicitly unsupported stairs/balconies/functional doors without an error. Conversation explanations and finish responses do not change the scene.

Provider context stays bounded: six recent messages, at most12 structure summaries, a compact selected structure template/role summary and selected Part identity/type/pose/scale. No unlimited history, mesh data, camera frames, credential values or unrestricted tool execution. New context fields are optional for compatibility. The8KiB request limit remains enforced. Progress is status-only; model internal reasoning is not displayed.

## Native Gemini decoder compatibility

Live tests found generic upstream HTTP400 INVALID_ARGUMENT for the combined nested assistant schema. Changing only the root union was insufficient; a minimal structured schema succeeded. The native decoder now receives a small object with a bounded response JSON string. The complete runtime schema remains in system guidance, and the decoded object must pass the original strict discriminated union and all existing geometry, target, attribute and placement checks. This reduces decoder complexity without accepting invalid scene data or adding a second model call. Compatible/Ollama adapters share the same transport and validation. Mocked native tests verify the small schema and envelope; malicious or malformed nested responses remain rejected.

An actual model response also confused total building height with height per storey. Explicit instructions now define height in per-storey meters (default3, range2.5–5); the invalid candidate was rejected, not corrected silently. A separate false rejection of standard CSS purple came from linear-space HSL comparisons. Display sRGB comparisons and a purple hue band retain ordinary purple shades while rejecting blue. Tests preserve both acceptance and rejection behavior.

## Refinement and geometry

“Add three windows to the second floor” now adds to that floor's current count instead of replacing it silently. Upper-floor segmented layouts support up to six windows where geometry fits; ground-floor door/window placement remains constrained by actual openings and can reject excessive counts. No collision checks were weakened. In particular, a tightly fitted selected door/window may require a Structure layout change rather than a component-only move/resize. Unsupported requests explain alternatives.

The exact detailed two-story/yellow-wall/purple-wooden-door/six-window-three-per-floor/pink-roof request remains supported and tested. Subsequent roof, additional-window and width proposals retain the same structure identity and unrelated appearance. Fixed door/window panels occupy segmented openings; these are not hinged or engineering/physics simulations. Template layout rebuilding requires intact generated metadata; arbitrary manually modified/imported geometry uses ordinary component operations.

## Voice and existing controls

Speech recognition remains an alternative input method. A final transcript fills the same editable composer; new users review and Send manually. Existing explicit auto-submit preferences remain available, while interim/repeated finals cannot generate duplicate requests. Permission/network/unsupported-browser errors keep typed input intact. The browser's recognition service is separate from Gemini and may use an external service. Build, mouse, Inspector, Part/Structure selection, one-hand movement, two-hand scale/yaw, colors/materials, save/load and exact Undo/Redo remain on their established paths. Gesture thresholds, pinch debounce and popup prevention were not changed.
